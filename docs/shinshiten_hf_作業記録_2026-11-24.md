# shinshiten 実素材と spi HyperFrames 作業記録（2026-11-24）

## shinshiten の実素材

- 自動取得では `--allow-card` が card だけを除外対象から外す。`--no-person` では Gemini に人物の顔・被害者・遺族・血・遺体・特定可能な個人を除外させ、現場周辺の背景や公的資料に限定する。判定が失敗した場合や `--no-gemini` との併用時は新規の素材を採用しない。
- 手動同期は各動画の `script.json` のカットを読み、文字列と辞書の `real_src` を共通の履歴形式に変換する。カット別の `sources.md` 行から不足 URL を補い、同じ行にある法廷画 ID を `court_src.json` と照合する。動画フォルダ名・カット ID・URL の組で照合するため、素材の差し替え履歴も残る。
- 実データの dry-run は読み取り181件、追記予定180件。既存履歴のコピーへの実書き込みは初回180件、2回目0件で、2回目のファイル内容も一致した。
- 指定された3フラグを一時台本で実行し、新規採用0件を確認した。カード除外条件の切替と motion の除外維持はダウンロードを置き換えた最小試験で確認した。Gemini API は呼び出していない。

## spi の組み立て

章頭（`chapter` または `yt_chapter`）または山場（`peak`）で、通常の画像・モーションカードを指定したカットに `"hf_3d": true` を追加する。台本順で先頭2件まで対象にする。対応する書き出し済み MP4 を作業フォルダの `images/_hf/<カットID>.mp4` に置く。

HyperFrames は事前の素材制作に使う。日次組み立てでは既存のカードを用意してから、指定素材があれば音声尺に合わせて FFmpeg で一時ファイルに変換し、尺確認後に置き換える。素材なし・破損・変換失敗・90秒のタイムアウト時は通常カードの経路を使う。素材の更新はキャッシュに反映する。書き手と台本点検は手動指定のため編集していない。

試験では生成した短い MP4 の尺調整と、破損 MP4 の採用拒否・既存出力保持を確認した。変更した Python 3本は py_compile 成功。日次動画の通し組み立ては未実施。

## HyperFrames 実測

手動起動の GitHub Actions は Ubuntu で HyperFrames 0.9.19 を使い、SwiftShader を明示する。check と render の経過秒、終了コード、render 出力バイト数をステップサマリーに記録する。テレメトリを無効にし、three と GSAP は同梱した assets/lib を参照する。コンパイラによる Google Fonts の取得は手元の初回 check で発生した。Actions の実行結果は未取得。

Windows、Node v26.13.0、Chrome、HyperFrames 0.9.19 でコマンド疎通を確認。初回の npm 証明書エラーは Node のシステム CA 利用で解消した。check は終了コード0で WebGL ドライバー警告が7件。render は CLI 表示で software GPU、18.1秒。MP4 は8.0秒、4,077,614バイト。
